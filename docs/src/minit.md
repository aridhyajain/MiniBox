# src/minit.c

## Purpose
The tiny init behind `minibox run --init`. Normally the user's command *is* the container's PID 1 (it replaces the
cloned child with `execvp`). With `--init` the cloned child stays PID 1 and becomes this small program, and the command
runs as its child (PID 2):

```
without --init:   PID 1 = the command
with    --init:   PID 1 = minibox-init  --fork+exec-->  PID 2 = the command
```

The init does three things and nothing else: **forward signals** to the command, **reap every child** it finds, and
**exit with the command's status**. Docker's `--init` (the `tini` program) works the same way. It is opt-in; without the
flag nothing changes. It fixes: zombies piling up under a PID 1 that never calls `wait()`, SIGTERM being dropped by a PID 1
without a handler (so `stop` always ended in SIGKILL / 137), and a program that becomes PID 1 (busybox `timeout`)
being unable to kill itself.

`minit_run` runs **inside the container**, after `pivot_root`, hostname, network and the cgroup handshake, i.e. exactly where
`execvp` used to be (`child_main` in `src/container.c`).

## How it works, step by step
1. `prctl(PR_SET_NAME, "minibox-init")` – the process shows up as `minibox-init` in `/proc/1/comm` and `ps`.
2. **Block** SIGCHLD, SIGTERM, SIGINT, SIGHUP, SIGQUIT, SIGUSR1, SIGUSR2 with `sigprocmask`. A blocked signal stays *pending*
   instead of being dropped (the kernel drops signals sent to a namespace's init from outside unless init has a handler or has
   them blocked), so the init needs no signal handlers at all, and the main loop is an ordinary loop.
3. `fork()`. In the child: reset those signals to `SIG_DFL` (minibox's SIGINT/SIGTERM handlers from `container.c` were inherited),
   restore the original signal mask, `execvp` the command. If exec fails it prints `exec <prog>: <reason>` and exits **127**
   (not found) or **126** (cannot execute), like a shell. If `fork` fails the init prints `minibox: init: cannot start <prog>: fork: <reason>` and returns 127.
4. Loop: **reap**, then **wait** for a signal.
   - *Reap*: `waitpid(-1, &status, WNOHANG)` repeatedly until it returns 0 (children exist, none dead) or `ECHILD`. `-1` means "any child",
     which includes every orphan reparented to PID 1, however deep in the tree it was. A loop is needed because SIGCHLD is not queued: three
     children dying together can produce one signal. `EINTR` is retried. If the reaped PID is the command, its status is kept.
   - *Wait*: `sigtimedwait` (1 s timeout) for one of the blocked signals. SIGCHLD only wakes the loop. Any other signal is forwarded to the
     command with `kill(pid, sig)`. The timeout is only a safety net: every round reaps first, so a missed SIGCHLD delays reaping by at most 1 s.
5. As soon as the command has been reaped, return its status as an exit code: `WEXITSTATUS`, or **128 + signal** if it was killed (143 for SIGTERM,
   137 for SIGKILL). Returning ends PID 1, and the kernel kills everything still in the namespace.

## Interactive use (stdin is a terminal)
The init does **not** call `setsid`, `setpgid` or `tcsetpgrp`: the command stays in the same foreground process group as before, so
Ctrl+C, Ctrl+Z and Ctrl+\ are delivered to it by the terminal exactly as without `--init`. To avoid delivering the same signal twice, signals whose
`si_code` is `SI_KERNEL` (generated by the tty driver) are **not** forwarded; signals sent with `kill()` (`SI_USER`, e.g. `minibox stop` from the host,
or `kill 1` from inside) are. Ctrl+C also reaches `minibox` itself, whose handler sends SIGKILL to PID 1 – unchanged from before.

## Functions
| Function | Inputs | Returns | Errors / side effects |
|----------|--------|---------|-----------------------|
| `int minit_run(char *const argv[])` | the command vector, NULL-terminated | exit status for PID 1: command's exit code, 128+N if killed by signal N, 127 (fork failed / not found / init failure), 126 (cannot execute) | sets the process name, blocks 7 signals (stays blocked in the init), forks the command, reaps all children, forwards signals; messages on stderr |
| static `build_signal_set(set)` | out set | – | SIGCHLD + the six forwarded signals |
| static `exit_code_from_status(status)` | `waitpid` status | 0..255 | exit code, or 128+signal; 127 for an unexpected status |
| static `exec_main_child(argv, old_mask)` | command, original mask | never returns | `sigaction(SIG_DFL)` x7, `sigprocmask`, `execvp`; `_exit(126/127)` on failure |
| static `start_main_child(argv, old_mask)` | – | child PID, or -1 | `fork`; prints the error |
| static `reap_children(main_pid, &status)` | – | 1 = command reaped, 0 = not yet, -1 = no children although the command was never reaped | `waitpid(-1, WNOHANG)` loop, `EINTR` retried |
| static `forward_signal(main_pid, info)` | `siginfo_t` | – | `kill(main_pid, sig)` unless `si_code == SI_KERNEL`; `ESRCH` ignored |
| static `wait_for_event(set, main_pid)` | – | – | `sigtimedwait` (1 s); `EAGAIN`/`EINTR` are normal |

## System calls used and why
- `prctl(PR_SET_NAME)` – recognisable name in `ps` and `/proc/1/comm`.
- `sigprocmask`, `sigtimedwait` – receive signals synchronously instead of in handlers.
- `fork`, `execvp`, `_exit` – start the command.
- `waitpid(-1, WNOHANG)` – reap the command and all orphans.
- `kill` – forward signals. `sigaction` – reset handlers in the child.

## OS concept
PID 1 of a PID namespace is special: it inherits every orphan (and must `wait()` for them, or they stay zombies), and it only receives
signals from outside the namespace that it has handled or blocked. A container "init" exists to do exactly this job.

## How to test
```sh
sudo bash tests/init_test.sh                       # all --init checks (PID 1, reaping, exit codes, stop, limits, veth, exec)
sudo ./minibox run --init -- sh -c 'exit 7'; echo $?          # 7
sudo ./minibox run -d --init --name t -- sleep 300 && time sudo ./minibox stop t   # quick, exit code 143
sudo ./minibox exec t -- cat /proc/1/comm          # minibox-init
```
`minit_run` can also be tried without root in a small test program that calls it directly (it works as any process, not only as PID 1);
see the DEVLOG entry of this change.
